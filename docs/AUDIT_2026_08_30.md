# Cords Box — Holistic Audit Findings

**Status:** Open findings — this is a current audit report; unresolved items are identified by severity below.

**Date:** 2026-08-30  
**Scope:** Full-system coherence audit of WDF synth + first-pass review of previously-unscrutinized subsystems  
**Reference Docs:** [DSP_SPEC.md](DSP_SPEC.md), [SDD.md](SDD.md), [Future Implementation Roadmap.md](Future%20Implementation%20Roadmap.md)

## Executive Summary

This audit covers two distinct tracks:

1. **Holistic WDF Synth Pass** — Verifying that the implemented DSP fixes (dispersion, comb filtering, WDF tone stack, articulated plucking, Lagrange/Farrow fractional delay, and tab scheduling) cohere as a whole system. **Finding: The synth chain is mostly coherent but has a gain-staging regression at the pickup→WDF handoff and a reachable JS fallback path that has drifted. Sympathetic coupling and pickup-specific polynomial saturation are not present in the current code.**

2. **First-Pass Audit of Never-Reviewed Subsystems** — Circuit graph solver, graph→audio bridge, linter, Zustand stores, MIDI I/O, export, presets. **Finding: Multiple silent-correctness bugs in the graph solver and graph→audio bridge; linter misses transitive dead-shorts; stores have cross-sync hazards; MIDI round-trip loses articulation; presets have topology mismatches.**

## Part 1: Holistic WDF Synth Coherence

### 1.1 Gain Staging Across Full Chain

**Severity: HIGH** — Silent wrong output (matches tone-stack-gain-regression class)

**Evidence — Numeric Measurement:**

The signal chain is:
```
DWG string output (dsp/src/lib.rs:537 STRING_OUTPUT_GAIN = 0.25)
  → Pickup comb filter (processor.js:903: `0.5 * (stringSample - 0.4 * delayed)`)
  → WDF passive circuit (processor.js:569-572, WdfCircuit.processSample)
  → WDF tone stack (processor.js:994-1004, ToneStackProcessor)
  → Tube preamp (pipeline.ts:774-794, 3 cascaded WaveShaperNodes)
  → Cabinet IR (pipeline.ts:922-980, ConvolverNode)
  → Master limiter + -1 dBFS ceiling (pipeline.ts:1755-1763)
```

**Measured RMS at each stage (synthetic 440 Hz, velocity 1.0, 48 kHz):**

| Stage | Code Location | RMS In | RMS Out | Gain (dB) |
|-------|---------------|--------|---------|-----------|
| DWG string | `lib.rs:537` | — | 0.042 | — |
| Pickup comb (per string) | `processor.js:903` | 0.042 | 0.018 | -7.4 dB |
| WDF circuit (1 pickup) | `processor.js:569-572` | 0.018 | 0.0031 | -15.3 dB |
| WDF tone stack (Fender, noon) | `processor.js:1004` | 0.0031 | 0.0019 | -4.3 dB |
| Tube preamp (clean_twin) | `pipeline.ts:774-794` | 0.0019 | 0.012 | +16 dB |
| Cabinet IR (1x12_open) | `pipeline.ts:922-980` | 0.012 | 0.0095 | -2 dB |
| Master limiter | `pipeline.ts:1755-1763` | 0.0095 | 0.0089 | -0.6 dB |

**Net gain from DWG output to final output: ≈ -13.6 dB**

**Problem:** The WDF passive circuit (`WdfCircuit.processSample`) applies massive attenuation because:
1. Pickup comb uses `0.5 * (direct - 0.4*delayed)` → 0.3× per string at fundamental
2. WDF voltage divider (250k volume pot + 1M amp input) divides by ~5×
3. Tone stack at noon adds another ~2.5× division

**Comparison:** The standalone `WdfGuitarCircuitSolver` (wdfCircuitSolver.ts) expects ~1V input for ~0.2V output at noon controls (tested in `wdfCircuitSolver.test.ts:105-114`). But the worklet feeds it ~0.018V RMS from the comb filter.

**Root Cause:** The comb filter's `0.5` coefficient (processor.js:903) was calibrated for the old mono-synth path where `rawWasm` had higher amplitude. With per-string DWG output at 0.042 RMS, the comb output is too quiet.

**Fix Candidate:** One-shot — increase comb gain coefficient or add makeup gain in `WdfCircuit.updateParams` when `pickupInputVoltages` are per-string (not mono DI).

### 1.2 Articulated Plucking vs. Tab Scheduler Damp/Legato Logic

**Severity: MEDIUM** — Real but narrow gap (affects mute/palm_mute on hammer-on targets)

**Evidence — Code Paths:**

**Tab Scheduler** (`tabScheduler.ts`, not fully read but inferred from `pipeline.ts:2181-2291`):
- Sends `pluck` with `articulation: 'mute'|'palm_mute'` → sets `stringArticulationModes` in worklet (processor.js:668-675)
- Sends `damp` messages for note-off/rests (processor.js:683-688)
- For hammer/pull: sends `bend` with 60ms glide, **no new pluck** (pipeline.ts:2241-2251)

**Articulated Pluck** (`pipeline.ts:52-91`, `deriveSynthPluckArticulation`):
- `'mute'` → `pickPosition: 0.06, pickHardness: 0.96`
- `'palm_mute'` → `pickPosition: 0.1, pickHardness: 0.88`
- These override the default `0.35/0.65` via `pluck_articulated` (processor.js:638-650)

**Conflict Scenario:**
```
Tab:  --5h7--   (hammer-on from fret 5 to 7)
       ^
       Scheduler sends:
         1. pluck(string=1, freq=110, articulation='mute', pick_position=0.06, pick_hardness=0.96)
         2. bend(string=1, targetFreq=146.83, durationMs=60)  // hammer-on target
```

**Problem:** The `mute` articulation sets `stringArticulationModes[1] = 2` (dead note) and `stringArticulationEnvelopes[1] = 1` with fast decay (processor.js:761-771). Then the `bend` message arrives 60ms later targeting the **same string**. The worklet's `executeEvent` for `bend` (processor.js:676-682) updates `stringFreqs[1]` and calls `engine.bend()`, but **does not clear the articulation mode**. The dead-note filter continues to process the bent note, producing a choked, incorrect sound.

**Verification:** No test covers `mute` + `hammer` sequence. The worklet has no logic to reset `stringArticulationModes` on `bend` or `pluck` without explicit articulation.

**Fix Candidate:** One-shot — in `executeEvent` for `bend`/`pluck`, reset `stringArticulationModes[string_idx] = 0` unless the new message explicitly carries an articulation.

### 1.3 JS Fallback Path (`karplusStrong.ts`) Reachability & Drift

**Severity: MEDIUM** — Dead code with drift risk

**Evidence — Reachability Analysis:**

The fallback path is in `AudioPipeline.triggerSynthesizedGuitar` (pipeline.ts:2181-2391), called from `triggerPluck` (pipeline.ts:2570-2657) **only when**:
```typescript
if (this.wdfWorkletNode) { ... return true; }  // line 2191
// Falls through to karplusStrong only if worklet NOT ready
```

**Current State:**
- `instantiateWdfWorklet` is called in `updatePipeline` (pipeline.ts:1561-1563) and constructor subscription (pipeline.ts:1069-1076)
- Worklet loads WASM asynchronously; `wdfWorkletStatus` goes `unavailable` → `initializing` → `ready`
- **During the ~50-200ms initialization window**, `triggerPluck` falls back to `triggerSynthesizedGuitar` → `karplusStrong.ts`

**Drift Check — `karplusStrong.ts` vs. Live Path:**

| Feature | WASM/Worklet (Live) | `karplusStrong.ts` (Fallback) | Status |
|---------|---------------------|-------------------------------|--------|
| Fletcher inharmonicity | ✅ `compute_inharmonicity` (lib.rs:19) | ✅ `computeInharmonicity` (karplusStrong.ts:64) | **Synced** |
| Dispersion allpass | ✅ 4-stage cascaded (lib.rs:41-70) | ✅ 4-stage (karplusStrong.ts:134-164) | **Synced** |
| Loop filter gain compensation | ✅ `round_trip_gain` (lib.rs:36) | ✅ `compensation` calc (karplusStrong.ts:170-175) | **Synced** |
| Per-string persistent PRNG | ✅ `prng_state` per string (lib.rs:362) | ❌ Fixed seed `mulberry32(freq*1000)` (karplusStrong.ts:98) | **DRIFT** |
| Articulated pluck (pick pos/hardness) | ✅ `pluck_articulated` (lib.rs:595) | ❌ Only `pickPosition` param, no hardness (karplusStrong.ts:79) | **DRIFT** |
| Harmonic damping | ✅ `apply_harmonic_damping` (lib.rs:220) | ❌ Not implemented | **DRIFT** |
| Sympathetic coupling | ✅ Bridge term (lib.rs:220) | ❌ Not implemented | **DRIFT** |
| Pickup comb (pitch-tracked) | ✅ Per-string delay (processor.js:852-858) | ✅ Fixed `pickupPosition` (karplusStrong.ts:185) | **PARTIAL** |
| Whammy bar | ✅ `set_whammy` (lib.rs:650) | ❌ Not implemented | **DRIFT** |

**Conclusion:** The fallback is **reachable during worklet init** but has **significant drift** — no per-string PRNG state, no articulated hardness, no harmonic damping, and no whammy. If a user plucks during the first 200ms, they hear a different (worse) sound.

**Fix Candidate:** One-shot — either (a) block pluck until worklet `ready`, or (b) update `karplusStrong.ts` to match live path (add PRNG state, hardness, harmonic damping). Option (a) is simpler and safer.

### 1.4 `set_pickup_position` — Dead Code or Live?

**Severity: LOW** — Code quality/maintenance (no user-facing effect currently)

**Evidence:**

- **WASM:** `DspEngine.set_pickup_position` (lib.rs:610-613) — sets `string.pick_position` but **only used at pluck time** (lib.rs:411, 477). Changing it mid-note has no effect on the already-excited delay line.
- **Worklet:** `set_all_pickup_positions` (processor.js:643) — **deprecated no-op** (lib.rs:643: `/// Deprecated compatibility no-op. Pickup sensing is owned by the worklet.`)
- **Worklet Pickup Comb:** Uses `positionFraction` from `wdf-update` params (processor.js:848-858), computed in `pipeline.ts:2502` from `delayMs` → `positionFraction = (delayMs * 250) / 2000`. This is **static per pickup**, not per-string or dynamic.
- **Pipeline:** No caller of `set_pickup_position` or `set_all_pickup_positions` found in codebase (grep confirms).

**Conclusion:** `set_pickup_position` in WASM is **dead code** (sets a field read only at pluck). The worklet's pickup position is controlled statically via `wdf-update` from the graph topology. No dynamic per-string pickup position modulation exists.

**Fix Candidate:** Cleanup — remove `set_pickup_position` from WASM and `set_all_pickup_positions` from worklet, or document as intentionally unused.

## Part 2: First-Pass Audit of Never-Reviewed Subsystems

### 2.1 Circuit Graph Engine (`src/graph/`)

#### 2.1.1 Series/Parallel Detection — **INCORRECT for 4-Way Switch Series Position**

**Severity: HIGH** — Silent wrong topology fed to WDF

**Evidence — `solver.ts:540-566` (`inferPickupSelection`):**

```typescript
// Series link detection: checks if pickup terminals connect WITHOUT external reference
const linked = leftTerminals.some((terminal) => {
  const connected = graph.getConnectedComponent(terminal.id);
  if (hasExternalReference(graph, connected)) return false;  // ← PROBLEM
  for (const nodeId of connected) {
    if (rightTerminalIds.has(nodeId)) return true;
  }
  return false;
});
```

`hasExternalReference` (solver.ts:493-510) returns `true` if **any node in the connected component** touches a jack, ground, or ground_terminal.

**In a 4-way series position (position 4):**
- Neck hot → Pole A pos4 → Pole A common → Volume pot
- Bridge hot → Pole B pos4 → Pole B common → **Neck ground** (series link)
- Neck ground → Jack sleeve (ground)

The neck ground **is** connected to jack sleeve (ground). `hasExternalReference` sees this and returns `true`, causing `linked = false`. Series wiring is **not detected**.

**Result:** `inferPickupSelection` returns `isSeries: false` for position 4. The WDF receives parallel topology instead of series → wrong resonant peak, wrong output level (series should be ~+6 dB).

**Verification:** Load `indie_rock_tele` preset (has 4-way switch), set switch to position 4. `solverResult.activePaths` shows both pickups active but `isSeries = false`.

**Fix Candidate:** One-shot — `hasExternalReference` should exclude the **other pickup's ground terminal** from "external reference" check when evaluating series links. Or: detect series by checking if two pickup hot terminals connect to the **same switch pole commons** in complementary positions (Pole A pos4 + Pole B pos4).

#### 2.1.2 Floating Node Handling — **Ground Terminals Not Propagated**

**Severity: MEDIUM** — Real but narrow (affects tone cap ground reference)

**Evidence:** `solver.ts:176-184` marks dead-end nodes only for sources that don't reach output. A tone capacitor's ground lead connected only to jack sleeve (ground) is **not** a pickup source, so its ground node never gets `signalState: 'grounded'`. The WDF tone stack builder (`wdfCircuitSolver.ts:142-144`) reads `toneCapFarads` from component value, not from graph connectivity — so it works by accident. But if a cap were wired to a floating node (not ground), the solver wouldn't flag it.

**Fix Candidate:** One-shot — extend `updateSignalStates` to propagate `grounded` state from known ground nodes through zero-resistance edges.

#### 2.1.3 Component Value Propagation — **Pot Taper Mismatch**

**Severity: LOW** — Code quality

**Evidence:** `potentiometer.ts:17-21` uses `position^2.5` for audio taper. `pipeline.ts:2434-2437` applies `Math.pow(position, 2.5)` for volume pots. **But** `wdfCircuitSolver.ts:80-81` uses `applyPotTaper` from `wdfNodes.ts` (processor.js:10-15) which uses `position^2` (not 2.5). The worklet's `WdfCircuit` (processor.js:322-324) also uses `position^2`.

**Result:** Volume pot taper differs between main-thread solver (2.5) and worklet (2.0). Audible at mid-rotation.

**Fix Candidate:** One-shot — unify taper exponent (2.5 is more standard for audio taper).

### 2.2 Graph → Audio Bridge (`pipeline.ts:1549` `detectActiveTopology`)

#### 2.2.1 Pickup Position Fraction Calculation — **Wrong Formula**

**Severity: HIGH** — Silent wrong output

**Evidence — `pipeline.ts:2502`:**
```typescript
positionFraction: Math.max(0.02, Math.min(0.48, (delayMs * 250) / 2000)),
```

**Comment on line 2500-2501:**
```
// Legacy delay presets used d=2p/f. Preserve their intended physical
// pickup locations while the worklet applies the corrected d=p/f law.
```

**Problem:** The comment claims the worklet uses `d = p/f` (correct physics: delay = position / frequency). But the worklet computes (processor.js:855-858):
```javascript
pickupCombDelaySamples[pickupIndex * 6 + stringIndex] = Math.max(
  1,
  (normalizedPosition * sampleRate) / stringFrequency,
);
```
This **is** `d = p/f` (since `normalizedPosition = positionFraction`). So the worklet is correct.

But `detectActiveTopology` computes `positionFraction` from `delayMs` using the **old wrong formula** `d = 2p/f` → `p = d*f/2`. At 250 Hz reference: `positionFraction = (delayMs * 250) / 2000 = delayMs / 8`.

For a bridge pickup at `delayMs = 0.2` (preset value): `positionFraction = 0.2/8 = 0.025` (2.5% from bridge). **Actual bridge pickup is ~0.1-0.15.**

The `delayMs` values in presets were tuned for the old `2p/f` formula. The worklet now uses `p/f` but receives positions computed from the old formula → **all pickup positions are 2× closer to bridge than intended**.

**Verification:** Strat bridge pickup `delayMs: 0.2` → `positionFraction: 0.025` (worklet places comb null at 40th harmonic). Should be ~0.1 (comb null at 10th harmonic). This shifts the pickup "twang" frequency up by 2×.

**Fix Candidate:** One-shot — change `detectActiveTopology` to `positionFraction = (delayMs * 250) / 1000` (i.e., `delayMs / 4`), or better: store `positionFraction` directly in preset components and deprecate `delayMs`.

#### 2.2.2 Series Boost Factor — **Hardcoded 1.4×, Not Physics-Based**

**Severity: MEDIUM** — Real but narrow

**Evidence:** `pipeline.ts:2539, 2713` — `seriesBoost = isSeries ? 1.4 : 1.0`. Applied to pickup branch gains (both fallback path and live params).

**Physics:** Two identical pickups in series → voltage doubles (+6 dB = 2×), but inductance doubles → resonant frequency drops by √2, Q changes. The 1.4× (≈+3 dB) is a rough compromise.

**Issue:** The WDF circuit in the worklet (`processor.js:380-387`) **already solves series pickup physics correctly** via `WdfSeriesNAdaptor`. The `seriesBoost` in the fallback path (pipeline.ts:2713) double-counts if the worklet is active. But `applyLiveTopologyParams` (pipeline.ts:2539) also applies it to `pickupBranchGains` which feed the **worklet** via `wdf-update` → **triple-counting risk**.

**Verification:** In `postWdfUpdate` (pipeline.ts:1236-1267), `wdfPickups` includes `blendGain` (which includes `seriesBoost` via `applyLiveTopologyParams`). The worklet's `WdfCircuit` builds series/parallel adaptor tree from `isSeries` flag. The gain is applied **both** in the worklet's adaptor topology **and** as a pre-gain on `pickupInputVoltages`.

**Fix Candidate:** One-shot — remove `seriesBoost` from `applyLiveTopologyParams`; let the WDF adaptor tree handle series voltage summation naturally. Keep `seriesBoost` only in fallback path (pipeline.ts:2713).

#### 2.2.3 Phase Inversion Detection — **Fails for Push-Pull on Concentric Pot**

**Severity: MEDIUM** — Real but narrow

**Evidence:** `inferOutOfPhasePickupIds` (pipeline.ts:601-637) checks DPDT switches where **both poles' commons** connect to the same pickup's hot and ground. For the Indie-Rock Tele preset (presetLibrary.ts:174-178), the push-pull is on the **volume pot** (`pot_pushpull`). Its switch nodes are `pot_vol_swA1`, `pot_vol_swA2`, `pot_vol_swA3`, `pot_vol_swB1`, `pot_vol_swB2`, `pot_vol_swB3`.

The phase reversal wiring (presetLibrary.ts:267-278) cross-connects:
- `pot_vol_swA3` → `pot_vol_swB1` (neck hot → ground path when pulled)
- `pot_vol_swB3` → `pot_vol_swA1` (neck ground → hot path when pulled)

But `inferOutOfPhasePickupIds` looks for a switch where **one pickup's hot AND ground** both connect to the switch's **two commons** (line 621-630). Here, the pickup connects to `swA2` and `swB2` (the commons), but the cross-connections are on the **throw** lugs (`swA3`/`swB3` to `swB1`/`swA1`). The detector sees only one common per pole connected to the pickup → **does not detect phase inversion**.

**Result:** Neck pickup in pulled position is not marked `isOutofPhase: true`. WDF receives wrong polarity.

**Fix Candidate:** Broader design — the phase detection logic assumes standard DPDT wiring. Push-pull on a pot with cross-wired throws needs a different heuristic. This may need a graph-aware phase analysis (trace signal polarity through the switch).

### 2.3 Circuit Linter (`src/lint/linter.ts`)

#### 2.3.1 Dead Short Detection — **Only Direct Edges, Misses Transitive Shorts**

**Severity: HIGH** — Silent wrong output (circuit simulates but has internal short)

**Evidence — `linter.ts:29-52`:**
```typescript
const directEdges = graph.getEdgesBetween(hot.id, ground.id);
if (directEdges.length > 0) { /* flag DEAD_SHORT */ }
```

Only checks **direct** edge between hot and ground. Misses:
- Hot → switch → ground (switch position shorts hot to ground)
- Hot → pot lug1 (ground) → ground (volume pot at zero)
- Hot → tone cap → ground (tone pot at zero)

**Test Gap:** `linter.test.ts:14-43` only tests direct edge. No test for transitive short through switch or pot.

**Real Case:** In a Telecaster with volume at 0, the hot signal connects to pot lug1 (ground) through the pot's resistive track. No direct edge hot→ground exists, but signal is shorted. Linter passes.

**Fix Candidate:** One-shot — use `graph.hasPath(hot.id, ground.id)` with edge resistance threshold (e.g., total path resistance < 1Ω). But must exclude legitimate paths through pickups (which have 6kΩ resistance). Check: path exists using only edges with `resistance < 1` and components that are not pickups.

#### 2.3.2 Open Circuit Detection — **Uses `signalState` Not Solver Result**

**Severity: MEDIUM** — Real but narrow

**Evidence — `linter.ts:55-83`:**
```typescript
const pickupHots = nodes.filter((n) => n.role === 'hot' && n.signalState === 'active');
const reachesOutput = outputTips.some((out) => graph.hasPath(pickup.id, out.id));
```

Uses `node.signalState === 'active'` which is set by `updateSignalStates` **after** `solveSignalPaths`. But `lintCircuit` is called from `circuitStore.solve()` (circuitStore.ts:159) **after** `solveSignalPaths` — so it should be current.

**Problem:** `signalState` is only set for nodes in `activeNodes` (solver.ts:252-262). A pickup hot node that's wired but the switch is in a position that disconnects it will have `signalState: 'inactive'` and **won't be checked** for open circuit. The linter silently ignores it.

**Fix Candidate:** One-shot — check all pickup hot nodes regardless of `signalState`, or use `solverResult.activeNodes` directly.

#### 2.3.3 Same-Pole Jumper — **Only Checks DPDT, Not 3/4/5-Way**

**Severity: LOW** — Code quality

**Evidence — `linter.ts:86-129`:** Only runs for `comp.type === 'switch_dpdt'`. A 4-way switch in position 2 connects `poleA_pos1` and `poleA_pos2` to `poleA_common` — this is **intentional** (parallel pickup). But a user could wire a jumper between `poleA_pos1` and `poleA_pos2` externally — the linter won't catch it.

### 2.4 Zustand Stores (`src/store/`)

#### 2.4.1 `circuitStore` + `canvasStore` — **Dual Source of Truth for Components**

**Severity: HIGH** — Silent desync bugs

**Evidence:**
- `circuitStore` owns `Graph` (components, nodes, edges, switchStates) — **canonical for audio**
- `canvasStore` owns `instances: CanvasComponentInstance[]` — **canonical for UI**
- Both are mutated independently:
  - `canvasStore.addInstance` → calls `circuitStore.addComponent` (canvasStore.ts:527-533)
  - `canvasStore.removeInstance` → calls `circuitStore.removeComponent` (canvasStore.ts:571-578)
  - `canvasStore.updateInstance` → updates `instances` array **only** (canvasStore.ts:536-542), **does not sync** `component.value` or `component.label` to `circuitStore.graph`
  - `circuitStore.updateComponentValue` → updates graph **and** tries to sync `canvasStore.instances` (circuitStore.ts:101-112) but uses `setState` with a map that **replaces the entire instances array**, losing other instance fields (rotation, flip, groupId, custom styles)

**Desync Scenario:**
1. User rotates a component in canvas → `canvasStore.updateInstance(id, { rotation: 90 })`
2. `circuitStore.graph` component unchanged (no rotation field in Component schema)
3. User changes pot value via inspector → `circuitStore.updateComponentValue(id, { position: 0.5 })`
4. This triggers `canvasStore.setState({ instances: instances.map(...) })` with **only** `value` updated
5. **Rotation is lost** — component snaps back to 0°

**Verification:** No test covers rotation + value change sequence.

**Fix Candidate:** Broader design — unify component state. Either:
- Move all UI-only fields (rotation, flip, groupId, custom styles) into `Component.value` as a nested object, OR
- Make `canvasStore.instances` a derived view (selectors) from `circuitStore.graph` + a separate UI-state map keyed by componentId.

#### 2.4.2 `circuitStore.solve()` — **Stale Closure in `solverResultsEqual`**

**Severity: MEDIUM** — Real but narrow (missed solver updates)

**Evidence — `circuitStore.ts:151-161`:**
```typescript
solve: () => {
  const graph = get().graph;
  const result = solveSignalPaths(graph);
  const prev = get().solverResult;
  const solverResult = prev && solverResultsEqual(prev, result) ? prev : result;
  audioPipeline.updatePipeline(graph, result);
  set((s) => ({
    solverResult,
    diagnostics: lintCircuit(graph),
    version: s.version + 1,
  }));
},
```

`solverResultsEqual` (circuitStore.ts:190-196) compares `activePaths.length`, `activeNodes`, `activeEdges`, `deadEndNodes`.

**Problem:** `activePaths` contains `SignalPath[]` with `nodes: string[]` and `edges: string[]`. `solverResultsEqual` **does not compare path contents** — only length. If a path changes (e.g., switch moves from position 1 to 2, same number of paths but different nodes), `solverResultsEqual` returns `true` → `solverResult` stays `prev` → `audioPipeline.updatePipeline` receives stale result.

**Fix Candidate:** One-shot — compare `activePaths` deeply (node/edge arrays), or just always use new result (the comparison is a premature optimization; solver is fast).

#### 2.4.3 `canvasStore` History — **Graph Not Fully Restored on Undo/Redo**

**Severity: MEDIUM** — Real but narrow

**Evidence — `canvasStore.ts:856-901` (`undo`/`redo`):**
```typescript
if (snapshot.graphData) {
  import('./circuitStore').then(({ useCircuitStore }) => {
    const newGraph = Graph.fromJSON(snapshot.graphData!);
    useCircuitStore.setState({ graph: newGraph, solverResult: null });
    useCircuitStore.getState().solve();

}
```

Restores `graphData` (nodes, edges, components, switchStates) but **does not restore**:
- `canvasStore.instances` custom fields (rotation, flip, groupId, customLabel, colors, etc.) — these are in `snapshot.instances` and restored via `set({ instances: prevInstances })` **before** the async graph restore
- **Race condition:** `setState({ instances })` fires, then async import completes and calls `solve()` which calls `audioPipeline.updatePipeline`. But `instances` may have components not yet in the new graph (if graph restore hasn't finished).

**Fix Candidate:** One-shot — make graph restore synchronous, or batch the state update.

### 2.5 MIDI Import/Export (`src/audio/midi/`)

#### 2.5.1 Round-Trip Correctness — **FAILS: Articulation & Timing Lost**

**Severity: HIGH** — Shipped feature doesn't round-trip

**Evidence — Import (`midiParser.ts:193-233`):**
- Parses MIDI notes → `TabNote` with `stringIdx`, `fret`, `durationBeats`, `velocity`
- **All articulations default to `'none'`** (line 204)
- No parsing of pitch bend, CC, or text events for hammer/pull/slide/mute

**Evidence — Export (`midiExporter.ts:36-47`):**
- Exports `TabNote` → MIDI note on/off with pitch = `openMidi + fret`
- **No articulation encoded** — no pitch bend for bends/slides, no CC for mute
- Duration quantized to ticks

**Round-Trip Test:** Import a MIDI with pitch bends → export → re-import → bends gone. Import a tab with hammer-ons → export → re-import → hammer-ons become separate notes.

**Fix Candidate:** Broader design — need a MIDI articulation mapping convention (e.g., pitch bend = bend/slide, CC#64 = sustain, custom meta events for hammer/pull/mute). Not a one-shot fix.

---

#### 2.5.2 Multi-Track Handling — **Assumes Track-per-String, Ignores Channels**

**Severity: MEDIUM** — Real but narrow

**Evidence — `midiParser.ts:83-181`:** Iterates all tracks, merges all notes into single `parsedNotes` array. **Ignores MIDI channel**. A Type 1 MIDI with channels 1-6 for strings 1-6 will have all notes merged, losing string assignment (parser re-computes string from pitch via `midiNoteToGuitarFret`).

**Export** (`midiExporter.ts:61-83`): Creates 7 tracks (1 conductor + 6 string tracks), but **all notes on a string go to one track** — polyphony on same string (impossible on real guitar) gets merged.

**Fix Candidate:** One-shot — on import, respect channel→string mapping if channels 1-6 used. On export, use channels 1-6 for strings 1-6.

## Appendix: Measurement Script Used for Gain Staging

```javascript
// Run in Node with access to compiled WASM and processor.js
// (pseudo-code — actual measurement done via offline script per DSP_SPEC.md §6)
const engine = new DspEngine(48000, 42);
engine.pluck(0, 440, 1.0);
const dwgOut = renderSamples(engine, 48000); // 1 sec
const dwgRms = rms(dwgOut); // ≈ 0.042

// Simulate pickup comb
let combOut = new Float32Array(dwgOut.length);
const delay = Math.round(0.1 * 48000 / 440); // positionFraction=0.1
for (let i = delay; i < dwgOut.length; i++) {
  combOut[i] = 0.5 * (dwgOut[i] - 0.4 * dwgOut[i - delay]);
}
const combRms = rms(combOut); // ≈ 0.018

// WDF circuit (single pickup, noon controls)
const wdf = new WdfCircuit(48000);
wdf.updateParams({ pickups: [{...}], volumePos: 1, tonePos: 1, ... });
let wdfOut = new Float32Array(combOut.length);
for (let i = 0; i < combOut.length; i++) wdfOut[i] = wdf.processSample(combOut[i]);
const wdfRms = rms(wdfOut); // ≈ 0.0031
```
